## A. The artefact chain

**A1. The committed environment could not reproduce the results.**
`Conda_Env/vina.yml` pinned Python 3.11.15, NumPy 2.4.3, pandas 3.0.1, RDKit
2025.9.6 and SciPy 1.17.1. Appendix B reports 3.12.12, 2.3.4, 2.3.3, 2025.09.1
and 1.16.2, and states that most PoseBusters verdicts are tied to that exact RDKit
release, because its distance-geometry bounds set the bond-length and bond-angle
tolerances and its UFF supplies the internal-energy reference ensemble. The file
therefore rebuilt an environment that could not reproduce the validity verdicts.
Regenerated from the live environment, which matches the appendix exactly.

**A2. Two load-bearing patches live outside version control.** The PoseBusters
`energy_ratio.py` fix, without which `bust()` aborts on any ligand UFF cannot
parameterise, and the DiffDock seed hook, without which its sampling is
irreproducible. Both are described in Appendix B and neither is in the repository.
The pipeline now asserts both rather than assuming them.

**A3. DiffDock determinism is not what the config says.** The config on disk
carries `inference_seed: 42`. Counting the seed patch's `[repro] seeded` marker in
the stored run logs gives 0 for the benchmark, 0 for the Orai control and 24 for
the Orai experimental panel. The benchmark and control runs were unseeded single
draws and cannot be redrawn; only the experimental arm can. Appendix B states the
same asymmetry, so the document was right and the config was misleading.

**A4. Three inputs must never be regenerated.** The Fr0 receptor passed through an
unguarded OpenMM minimisation and differs by 0.394 Å between two preparations; the
prepared ligand PDBQTs come from a Meeko version whose successor changes atom
order and `TORSDOF`; and `exhaustiveness_arm_status.json` is the sole surviving
record of the gnina wall clock Appendix B cites. The pipeline refuses all three
under every run mode.

## B. Canonical trees

**B1. The current trees are the ones whose names read like scratch.** There are 57
directories under `posebusters_results/` and 22 under `pandamap_results/`.
Generation order, oldest first, is `*_PRE_FR0` and `*_PRE_EXH128` and
`*_UFFON_backup_*`, then the plain name, then `_matched`.

Settled by checksum rather than naming. Every one of the 39 short-build figures
was md5-matched against every PNG under the three output roots. All regenerable
assets resolve to the `_matched` trees and none to the plain ones. The full
verified index is section F below.

**B2. The regeneration guide was numbered against a document that no longer
exists.** Its figure index read from `Thesis.lof`, the retired full build, now
under `thesis_latex/obsolete/`. The short build numbers its floats differently and
has 39 figures against the guide's 36. Its output paths also predated the
matched-EquiBind migration for nearly every figure.

Root cause: the guide was maintained by hand, so nothing could notice that the
trees beneath it had moved. Fixed structurally rather than by patching. The guide
is now generated from the stage registry by `regenerate_guide.py`, with the figure
index rebuilt by checksum on every run, so a figure whose source moves shows as
moved. The hand-written original is kept as `REGENERATE_NOTES.md` for the
commentary that is not derivable from the registry. Section F below is the same
index in narrative form.

## D. The interaction pose-basis audit

**D1. It aborted for a cohort reason, not a data fault.** The audit joins the
PandaMap fingerprint table to the per-pose table and refuses a partial join. On the
canonical tree it joined 4,253 of 4,262 poses. The nine failures were all EquiBind,
in three complexes: 7D6O_MTE, 7FRX_O88 and 7M31_TDR.

Those three are among the five the analysed cohort excludes, because DiffDock
produced no poses for them. The five are 7B2C_TP7, 7D6O_MTE, 7FRX_O88, 7M31_TDR
and 8F4J_PHO. The PandaMap arm profiles 306 complexes while the cohort is 303.

The fix is `--ids-file` with a 303-id list derived from `per_pose_metrics.csv`,
stored as `analysed_cohort_ids.txt` beside it. **Re-running the PandaMap arm would
not have fixed this**, because the arm would still profile 306 complexes.

The guard was right to abort. Without it those nine poses would have been binned
into a null RMSD band and would have contaminated the standardisation reference
the whole audit rests on.

**D2. Appendix B was quoting the superseded arm.** Sixteen values moved. AutoDock
and DiffDock were unchanged throughout, the expected signature when only the
EquiBind pose set moved.

| Quantity | Was | Now |
| --- | --- | --- |
| Profiled pool | 4,156 poses over 302 complexes | 4,253 over 303 |
| Median deviation, share within 2 Å | 7.62 Å, 20.7% | 7.57 Å, 21.3% |
| Crude rank-1 F1, EquiBind | 0.455 | 0.471 |
| Standardised F1 triple | 0.529, 0.523, 0.508 | 0.532, 0.527, 0.513 |
| Placement share across band schemes | 81 to 85% | 80 to 87% |
| Site-filtered overlap, EquiBind | 0.611 over 141 | 0.629 over 155 |

No conclusion changed. The placement share is still roughly four fifths, the two
tools still swap under finer banding, the DiffDock lead still strengthens under the
site filter, and repairing both detection defects still leaves the ordering intact.

**D3. The appendix contradicted its own Results chapter.** The Results chapter
already quoted the canonical values, giving EquiBind's overlap as 0.380 and the
DiffDock lead as p = 0.014, while the appendix said 0.367 and 0.024. Resolved.

## G. Traps worth carrying forward

**G1. Filter to the raw pose cloud before reading Figure 23's medians.** The
caption specifies the raw cloud. Over both pose sets AutoDock's compactness reads
0.42 and the printed 0.62 looks wrong; on the raw set alone it is 0.623 and
correct. This caught the author of this document once, who reported the value as
unreproducible before spotting it.

**G2. Two different near-native gates are both printed.** Table 1's near-native
column is `rmsd <= 2` and is *not* conditioned on validity. Table 6's complexes
column is `pb_valid AND rmsd <= 2`. That is why AutoDock reads 202 complexes in one
and 199 in the other. Both are asserted so the difference cannot quietly collapse.

**G3. `--collapse-plots-only` is what makes the variant pins take effect.** Without
it, `--collapse-autodock-variant` and `--collapse-diffdock-variant` are accepted
and silently ignored.

**G4. `--exclude-preset meeko` alone is not enough for the validity figure.** The
report folds every surviving `autodock_mgltools*` key onto a bare `autodock`, so
the five unreported ladder rungs must also be excluded by name.

**G5. Holm correction is family-wise.** A p-value can move because a different
member of its family moved, not because its own data changed. That is why the
DiffDock silhouette collapsed p went from 0.516 to 0.548 when the EquiBind
silhouette went from 0.040 to 1.000.

## I. Byte-level regeneration validation

Sections A to H establish provenance: the image printed in the thesis is
byte-identical to a file on disk. That is a weaker claim than it sounds, because
it says nothing about whether the pipeline still produces that file.

`validate_regeneration.py` closes the gap. It re-runs each figure's generator from
the canonical inputs into a scratch directory that is thrown away, and compares the
bytes. Nothing it does can touch a canonical output.

**Result: 20 of 20 assets byte-identical**, across nine generators and all three
panels.

| Figures | Generator |
| --- | --- |
| 1 | `figure2_validity_yield.py` |
| 4 | `filmstrip_rank1_top5_top15.py` |
| 7, 39 | `pandamap_interaction_report.py` |
| 8 | `orai_pbvalid_yield_compare.py` |
| 9, 10 | `orai_pbvalid_tm_share_compare.py` |
| 11, 12, 23 | `orai_cross_tool_agreement_compare.py` |
| 13, 14, 25, 26 | `orai_pandamap_interaction_compare.py` |
| 15, 16 | `docking_effort_comparison.py` |
| 18, 19, 20, 21 | `autodock_exhaustiveness_returns.py` |

Nine figures are declared rather than tested, each with its reason recorded in the
harness. Figures 2, 3, 5, 6, 24 and 38 come from generators that write dozens of
outputs into a report directory and read a cache keyed to it, so a scratch run
would not exercise the published path. Figure 17 is author-drawn. Figures 22 and
27 are the hand-composed renders. Figures 28 to 37 come from a notebook whose
statistics are stable but whose rendering moves one to two per cent of pixels
between runs, so a byte comparison there would report a failure that is not one.

**I1. The check immediately found a real defect, in work done earlier the same
day.** Four figures regenerated differently: 13, 14, 25 and 26, all from
`orai_pandamap_interaction_compare.py`.

The cause was two arguments I had not passed. `--exp-posebusters-csv` and
`--bench-posebusters-csv` default to the plain trees. EquiBind's PandaMap pose
rank is a 999 placeholder, so the top-ten cap has to read its ranks from the
PoseBusters CSV. With the default paths the lookup fails and **all 324 EquiBind
pose rows are dropped without an error**. The four figures then render with only
two tools and differ from the published ones.

Nothing raised. The stats sidecar recorded it, in a line naming two tools where
the published run named three, but no exception and no warning. Passing the
canonical CSVs made all four byte-identical.

The defect was in the notebook stage as written, not in the thesis. Both the
stage and the validation harness now pass the two paths, with the reason attached.

**I2. What this does and does not establish.** It establishes that nine
generators, given the canonical inputs, still produce the published bytes. It does
not re-derive the inputs themselves: the per-pose table, the PoseBusters verdicts
and the PandaMap fingerprints are read as stored. Re-deriving those means
re-running the docking, which for two DiffDock arms is impossible in principle and
for the rest is days of compute.
