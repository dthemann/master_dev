### One thing worth correcting before we start

Your message ties the cleanup to upload size. Those are two different problems,
and only one of them is about the 81 GB.

Git tracks **175 MB across 3,283 files**. Every large results tree is already in
`.gitignore` and has never been uploaded. Moving 81 GB into `obsolete/` therefore
changes nothing about uploads.

What does drive upload size is small and specific: **120 MB of the 175 MB is old
notebooks and their backups**, six files of 26 MB or less. `.git` itself is
1.6 GB, which is what a fresh clone actually costs, and it is large because those
26 MB notebooks have been committed repeatedly.

So the plan has two independent halves, and they are worth judging separately.

- **Half A, disk and navigability.** Move the 81 GB. Real benefit: the directory becomes legible and a later deletion becomes safe, because everything moved is in one place with a manifest. No effect on uploads.
- **Half B, upload size.** Retire the superseded notebooks from git. Cuts the tracked tree from 175 MB to about 55 MB. Shrinking `.git` below 1.6 GB additionally needs a history rewrite, which I would not do without you asking explicitly.

## 2. The keep rule

I would not hand-pick what to keep. The reproduction pipeline already declares
it, and that declaration is machine-readable.

A path is kept if any of these mentions it:

1. a stage's declared outputs, from the 58-stage registry
2. a stage's command line, in `_build_reproduction_notebook.py`
3. any config in `Scripts/Docking/configs_thesis/`
4. the canonical-tree table in `repro_harness.py`
5. `thesis_expected_values.yaml` or `validate_regeneration.py`

Rule 2 is the one that matters. `Dockings/Benchmark_Equibind_cputimed` is not any
stage's *output*, but it is the `--equibind-dir` input to the cost stage behind
Table 6. An outputs-only rule would have moved it and broken a headline table. I
hit exactly that while preparing this plan, which is why the rule reads commands
as well.

The rule over-includes on purpose. Trees named only by a superseded config, such
as the Vinardo and Uni-Dock trees, are kept. Erring toward keeping costs disk;
erring the other way costs data.

### `results_current/`

You asked for the current results in a dedicated folder. I would build it from
**symlinks, not copies**. Copying would duplicate about 14 GB and immediately
create a second thing that can go stale, which is the failure mode this whole
exercise has been about. Symlinks give one obvious place to look while keeping a
single source of truth.

It would be generated by the notebook from the canonical-tree table, so it cannot
drift, and it would carry the run manifest and the assertion report alongside.

If you would rather have real copies, say so and I will make it copies. It is a
one-word change and I would rather you chose than have me assume.

## 6. How I would do it safely

1. **Dry run first.** Print every path with its size and destination, change nothing, and hand you the list.
2. **Move, never delete.** `mv` within the same filesystem, so it is instant and reversible.
3. **Mirror the paths.** `X` moves to `obsolete/X`, so restoring is `mv obsolete/X X`.
4. **Write `obsolete/MANIFEST.md`** naming every path, its size, and the rule that moved it.
5. **Add `obsolete/` to `.gitignore`** before moving anything, so nothing is ever staged.
6. **Move in stages**, verifying between each: `pandamap_results` first because it is 54 GB and the least entangled, then `Dockings`, then `posebusters_results`, then the notebooks.

## 7. How I would prove nothing broke

After each stage, and again at the end:

1. `Thesis_Reproduction.ipynb` in verify mode. **All 58 stages must still report their outputs present.** This is the real test: the registry knows every input the pipeline needs.
2. `thesis_assertions.py`. **All 257 checks must still reproduce.**
3. `validate_regeneration.py`. **All 20 assets must still regenerate byte-identically.** This one is decisive, because it re-runs the generators against whatever survived the move.
4. `latexmk` on the short build. 142 pages, zero undefined references.
5. `git status` must show no unexpected deletions of tracked files.

If any of the four fails, the move that caused it gets reverted from `obsolete/`
before going further. That is why the stages are separate.

## 8. What I would not do

- Delete anything, including the 15 GB git backup.
- Rewrite git history to shrink `.git`, unless you ask.
- Touch `Data/`, `thesis_latex/`, `Scripts/`, or any docked-pose tree the keep rule reaches.
- Move a tree named only by a superseded config. The rule keeps those deliberately.
