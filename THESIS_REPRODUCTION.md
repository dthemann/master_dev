# Thesis reproduction: development record

**Written 2026-09-02.** This document records how `Thesis_Reproduction.ipynb` and
its supporting files were built, and why each decision was made. Where a decision
follows from something the thesis states, the thesis passage is quoted or cited,
because the point of the exercise is that the code and the document agree.

Companion documents. `Scripts/Analysis/FINDINGS_2026-09-02.md` is the findings
record: every defect found, its evidence, what was changed and what remains, plus
an md5-verified index of all 39 short-build figures.
`Scripts/Analysis/REGENERATE.md` is generated by the notebook's last cell from the
same stage registry it executes, so it cannot drift; the hand-written guide it
replaced is kept as `REGENERATE_NOTES.md`.
`Scripts/Analysis/IMPLEMENTED_STATS_TESTS.md` records the statistical design and is
unaffected. This file covers the design of the pipeline itself.

---

## 1. Why a new notebook

`Master_Docking_AD_Full_Protein.ipynb` produced the reported results, and it is
kept unchanged as the historical record. It is not a reproduction artefact, for
four reasons that are independent of each other.

**It rewrites its own configuration.** Three cells load a YAML file, mutate it and
write it back with `yaml.safe_dump`, which also strips every provenance comment.
The worst of them sets `uff_minimize = True` on the EquiBind config. Appendix B
states the opposite: the in-protein UFF relaxation "was switched off for every run
reported in this thesis, the calibration benchmark and both Orai1 panels alike,
and the 308 committed benchmark run records confirm the setting." The config file
on disk agrees with the appendix and carries a header marking itself deprecated.
Running the notebook top to bottom therefore silently destroys the setting the
reported EquiBind numbers depend on.

**Page order is not execution order.** The transmembrane-exclusion step for both
Orai panels lives in the control section, but four cells in the earlier
experimental section read the file it writes. A reader running the notebook in
order gets stale inputs without any error.

**Reading a config was optional.** Most launchers used `cfg.get(key, default)`,
so a missing YAML key fell back to a code default. The benchmark EquiBind
launcher read `eb_cfg.get("uff_minimize", True)`, defaulting to the wrong value.
One cell, the Orai control EquiBind launcher, used a strict `cfg_req(key)` helper
that raises on a missing key. That is the pattern the new notebook uses
everywhere.

**A third of it is dead.** Abandoned arms (Vinardo, Uni-Dock, Uni-Dock2, the
Meeko-prepared trees), one-off repairs, two cells containing the bare token `de`
that raise `NameError`, and a markdown cell duplicated verbatim.

## 3. Design decisions

### 3.1 Verify first, run on request

The default run mode executes nothing. It walks all 66 stages, checks their
outputs exist, and asserts the thesis numbers. That takes a few minutes.

The reason is arithmetic. Appendix B records the AutoDock search at 4.73
wall-hours over 303 complexes and the gnina rescoring at 0.71 GPU-hours of measured
device occupancy (10.27 GPU-hours if the sixteen concurrent workers' elapsed times are
summed), and that is one arm of one panel. The exhaustiveness ladder is five
independent searches. The Orai control panel is 1,232 units across three tools.
A notebook that re-docks on every run would never be run, and one that re-docks
by accident would destroy irreplaceable trees.

### 3.2 Three determinism classes, decided by evidence

This is the substantive decision in the whole design, and it was settled by
measurement rather than by reading the configs.

The local DiffDock patch prints `[repro] seeded` when the seed hook fires.
Counting that marker in the stored run logs gives:

| Panel | Logs with the marker |
| --- | --- |
| Benchmark | 0 |
| Orai control | 0 |
| Orai experimental | 24 |

So the benchmark and Orai control DiffDock runs were unseeded single draws and
cannot be redrawn; the Orai experimental run can. Appendix B says exactly this:
the two Orai panels are matched on settings and "one difference remains, namely
the DiffDock sampler seed", and "the reproducibility hook that fixes it appears
in the experimental run logs and is absent from the control ones."

Had the configs been trusted instead, the classification would have been wrong.
`diffdock_docking_config.yaml` on disk carries `inference_seed: 42`, which was
true when the experimental panel ran and is not true of the two earlier runs. The
new configs record what actually happened: `inference_seed: null` on the two
unseeded arms, with the reason in the header.

Everything else is seeded and must reproduce byte for byte. Vina runs at seed 42,
the gnina and smina refinements carry their own seeds, EquiBind draws from thirty
fixed RDKit seeds and seeds the model per job, and the statistics are seeded too:
Appendix H specifies 2,000 bootstrap resamples and 10,000 permutations, both at
fixed seeds, and no unseeded RNG exists in any live analysis script.

The third class refuses to run under any mode:

- **The Fr0 receptor.** It passed through an unguarded OpenMM minimisation with a Langevin integrator. Two preparations differ by 0.394 Å all-atom, four conformers already exist on disk, and `run_orai_mgltools_arm.py` pins its sha256 for this reason. A fifth conformer would break the link between the docked poses and a specific receptor.
- **The prepared ligand PDBQTs.** A newer Meeko changes atom ordering, the torsion-tree root and `TORSDOF`, which is why the AutoDock driver takes `--prepared-inputs-from` instead of re-deriving them.
- **`exhaustiveness_arm_status.json`.** The only surviving record of the gnina wall clock Appendix B cites. A cached re-run overwrites the measured time with the cost of the cache lookup, and no backup exists.

A bug found during verification is worth recording. The first version of the
driver checked the force branch before the refusals, so forcing a stage bypassed
exactly the protections that exist for the irreversible cases. The refusals now
come first, and the test that catches it is in section 6.

### 3.3 Canonical trees, settled by checksum

There are 57 directories under `posebusters_results/` and 22 under
`pandamap_results/`. The naming is actively misleading: the directories that read
like scratch are the current ones. Generation order, oldest first, is
`*_PRE_FR0` and `*_PRE_EXH128` and `*_UFFON_backup_*`, then the plain name, then
`_matched`.

This was decided by checksumming the figures the thesis actually ships against
every candidate source. All 24 regenerable figure assets match the `_matched`
trees and none matches the plain ones. For example `media/media/image43.png`,
Figure 9, has md5 `80b9a1b9…`, which is the copy under
`_orai_matched_root/orai_pbvalid_tm_share_compare/` and not the one under the
plain `orai_pbvalid_tm_share_compare/`.

The canonical set is therefore `benchmark_matched_equibind`,
`cluster_crystal_pocket_matched_equibind`, `_orai_matched_root/*`,
`autodock_exhaustiveness_returns`, and the `_matched` PandaMap trees. The harness
holds this in one table and every stage reads its paths from it, so an analysis
cannot silently pick up the previous generation.

The `_matched` trees exist because of examiner item M5. Every EquiBind refinement
had run `--local_only` while AutoDock and DiffDock ran `--minimize`, so the arms
were not comparable. Re-refining EquiBind from the committed `__refRAW.sdf`, which
is the exact input the original refinement received, made the flag the only
variable. AutoDock and DiffDock rows are bit-identical between the two
generations; only EquiBind moved.

### 3.4 Configs are copies, not edits

The 26 files in `Scripts/Docking/configs_thesis/` are the current thesis configs
copied verbatim with a provenance header prepended. The generator asserts that
each output parses to the same dictionary as its source, so behaviour cannot
drift. The originals stay in place, so nothing that currently runs breaks.

Three configs carry a declared deviation, all of them DiffDock, and all of the
same kind: the old notebook applied `output_dir`, `log_dir`, `optimization` and
in one case `num_samples` in memory after loading the YAML. The file on disk
therefore never described the run that produced the poses. Those values are baked
in and the header says so.

Each header names the thesis section it implements, the floats it supports, the
tree it writes, the analysis tree that reads it, and its determinism class.

### 3.5 The Fr0 correction is per-method routing, not a comment

The subtlest thing in the pipeline. AutoDock docked the Fr0 frame into the
OpenMM-minimised receptor, but the main PoseBusters screen validates against the
raw PDB. The two differ by 0.815 Å heavy-atom RMSD, which costs Fr0 its validity:
73.9 per cent instead of 97.7.

The correction is a second PoseBusters pass with the `*_fr0corrected` configs, and
it applies to **AutoDock rows only**. DiffDock and EquiBind docked the raw
receptor, so applying the correction to them creates the mismatch rather than
repairing it. EquiBind's validity drops from 58.2 to 15.8 per cent when this is
got wrong, and the `.WRONG-RECEPTOR-quarantined-1854` directories on disk are that
mistake preserved. The new pipeline encodes the routing in separate stages with
the reason in each stage's note.

### 3.6 Figure 8 became a script

Figure 8, the PoseBusters-valid yield of the two Orai panels, had no committed
generator. It lived as a 14.8 KB inline notebook cell, which made it the one item
blocking a script-driven rebuild of the Results chapter.

It was lifted into `Scripts/Analysis/orai_pbvalid_yield_compare.py` with the
plotting body, layout constants, colour grammar and statistics unchanged. Only the
paths and the three variant pins became arguments. The extracted script reproduces
the shipped asset **byte-identically**, md5 `bbb5cf61…` matching
`media/media/image13.png`, and both its CSV outputs are identical to the stored
ones.

Two decisions are recorded in the script rather than left implicit. The
transmembrane-excluded CSV is deliberately **not** used, because the figure
measures geometry quality and must not be conditioned on placement; and the
deprotonated GSK-7975A duplicate is excluded, so the experimental panel is the
three intended compounds over four frames.

### 3.7 The environment file was wrong

`Conda_Env/vina.yml` pinned Python 3.11.15, NumPy 2.4.3, pandas 3.0.1, RDKit
2025.9.6 and SciPy 1.17.1. Appendix B reports Python 3.12.12, RDKit 2025.09.1,
NumPy 2.3.4, SciPy 1.16.2, pandas 2.3.3 and scikit-learn 1.8.0, and adds that
"most PoseBusters verdicts are tied to this exact version" of RDKit, because its
distance-geometry bounds set the bond-length and bond-angle tolerances and its UFF
supplies the internal-energy reference ensemble.

The committed file therefore rebuilt an environment that could not reproduce the
validity verdicts. It was regenerated from the live environment, which matches the
appendix exactly, and its header records what changed and why.

One patch is still not captured by any environment file, and cannot be: the local
fix to `posebusters/modules/energy_ratio.py` in site-packages. The notebook
asserts it is present rather than assuming it.

## 4. Two patches that live outside the repository

Both are described in Appendix B and neither is version-controlled. The notebook
checks for both and fails loudly if either is missing.

**PoseBusters `energy_ratio.py`.** The handler guarding the UFF parameter check
indexed `e.args[1]` on an assertion carrying a single argument. It therefore
raised `IndexError` of its own and aborted the whole `bust()` call instead of
returning the empty result the module defines for a failed check. Every pose of
any ligand UFF cannot parameterise, such as one carrying hypervalent sulfur, a
phosphate group or a coordinated metal, would have been discarded with no error
reported. The patch adds no check, changes no threshold and alters no pass
criterion.

**DiffDock `inference.py`.** Upstream DiffDock ships no seed option, so its
sampling differs on every run. The patch reads `DIFFDOCK_SEED` and seeds Python,
NumPy and Torch. Section 3.2 covers which runs it actually reached.

## 5. Findings

These came out of building and running the pipeline. None of them changes a
number the thesis prints; all of them are reported rather than acted on, because

### 5.1 Closed

Four canonical outputs did not exist and were regenerated on the canonical tree.

**Table 2's sidecar.** `topk_recovery_validity_gnina_arm.csv` existed only under
the superseded whole-protein tree. Regenerated on the matched tree it reproduces
every printed cell exactly: AutoDock 149 / 213 / 214, DiffDock 132 / 179 / 183,
EquiBind 57 / 83 / 83 at rank-1, top-15 and top-30 (nearest-copy endpoint; the
single-instance values 111 / 198 / 199, 103 / 167 / 169, 55 / 80 / 80 are the sensitivity arm).

**Table 22's source.** `validity_gate_cost.csv` and `bounded_claim.csv`, same
situation, now regenerated.

**The Orai ligand-level contrasts.** The sensitivity re-test that the Methods
commit to for every Orai cross-panel contrast had never been rerun after the
matched-EquiBind migration. Regenerating it moves two of 140 rows across the 0.05
threshold, and both moves favour the printed text:

| Contrast | Superseded tree | Canonical tree |
| --- | --- | --- |
| EquiBind silhouette, frame-ligand | p = 0.040 | p = 1.000 |
| AutoDock π-π stacking, frame-ligand | p = 0.051 | p = 0.037 |

The appendix paragraph on reference-free cluster quality states "No other
difference was detected" after discussing DiffDock's silhouette. That sentence is
correct on the canonical tree and would have been contradicted by the superseded
one. The DiffDock silhouette values the appendix quotes, medians 0.17 and 0.42
with δ = +0.53 and Holm p = 0.031 at the frame-ligand unit, reproduce exactly. Its
ligand-level p of 0.516 matches neither tree, reading 0.548 on the canonical one
and 0.419 on the superseded one, but all three are far above 0.05 and the
conclusion that the result is descriptive is unaffected.

**The Orai region-consensus analysis**, regenerated on the canonical tree.

### 5.2 Closed on 2026-09-02, after the first pass

**Figures 23, 24 and 39 shipped from pre-matched trees** while every other figure
in their families had moved. The three assets were refreshed from the canonical
trees and the surrounding prose reconciled. The figure count in the assertion
harness went from 21 to 24 byte-identical.

The prose was already largely on the canonical tree, which is what made the
figures the odd ones out. Figure 24's "39 of its 46 paired filtered clouds" and
"1.50 to 1.30", and Figure 39's "16.7 matched contacts against 18.9 missed" and
"12.0 to 12.6", all reproduce on the matched tree and none on the superseded one.
So the text had been updated after the matched-EquiBind migration and the images
had not.

Four numbers needed correction:

| Location | Was | Now | Why |
| --- | --- | --- | --- |
| Appendix, Figure 23 paragraph | Holm p 0.516 | 0.548 | Holm is family-wise, and EquiBind's silhouette moving shifted the whole family |
| Appendix, Figure 23 caption | 148 outliers | 163 | the refreshed panel's own annotation |
| Appendix, Figure 24 paragraph | AutoDock stability 0.77 to 0.78 at +0.29 | holding a median 0.78 at +0.27 | matched neither tree; both give 0.78 to 0.78 at +0.27 |
| Main body, cluster-quality sentence | "no cross-panel difference survives collapsing" | only DiffDock's Calinski-Harabasz survives | contradicted its own appendix on both trees |

The last is worth separating out, because it was not caused by the figure swap.
DiffDock's Calinski-Harabasz index is not significant at the frame-ligand unit,
at Holm p 0.074, and is significant at the ligand unit, at 0.031. The appendix
already said so, calling it a result that "reverses under that collapse" and
reading it as removal of within-ligand spread rather than new evidence. The main
body said the opposite. The correction makes the main body agree with the
appendix rather than changing what either concludes.

One claim became better supported rather than worse. On the superseded tree
EquiBind had the highest silhouette of the three tools, 0.825 against AutoDock's
0.792, which sits badly with the appendix saying AutoDock forms the
best-separated clouds and EquiBind the loosest. On the canonical tree EquiBind
reads 0.587, below AutoDock's 0.776, which is what the sentence describes.

The quoted values for all three figures are now asserted in
`thesis_expected_values.yaml` under `prose`, so the text and the figures cannot
separate again without the harness noticing.

### 5.3 Closed on 2026-09-02, after the second pass

**The interaction pose-basis audit now runs on the canonical tree.** It did not
need the PandaMap arm re-run, which is what the earlier reading assumed. The join
guard was firing for a mundane reason: the PandaMap arm profiles 306 complexes
while the analysed cohort is 303, so nine EquiBind poses in three excluded
complexes carried no RMSD. Restricting the audit with `--ids-file` fixes it. The
303-id file is derived from `per_pose_metrics.csv` rather than written by hand,
and lives beside it.

The guard was right to abort. Without it those nine poses would have been binned
into a `nan` RMSD band and would have contaminated the standardisation reference
that the whole audit rests on.

Running it revealed that Appendix B's "Interaction Fingerprints" section was
still quoting the superseded arm. Sixteen values moved. AutoDock and DiffDock
were unchanged throughout, as expected when only the EquiBind pose set moved:

| Quantity | Was | Now |
| --- | --- | --- |
| Profiled pool | 4,156 poses over 302 complexes | 4,253 over 303 |
| Median deviation and share within 2 Å | 7.62 Å, 20.7% | 7.57 Å, 21.3% |
| Crude rank-1 F1, EquiBind | 0.455 | 0.471 |
| Standardised F1 triple | 0.529, 0.523, 0.508 | 0.532, 0.527, 0.513 |

No conclusion changed. The placement share is still roughly four fifths, the
AutoDock and DiffDock standardised values still swap under finer banding, the
DiffDock lead still strengthens under the site filter, and repairing the two

One consistency problem was resolved along the way. The Results chapter already
quoted the canonical values, giving EquiBind's overlap as 0.380 and the DiffDock
lead as p = 0.014, while the appendix said 0.367 and 0.024. The appendix now
agrees with its own Results chapter.

## 6. Validation

Everything below was run, not asserted.

**The pipeline executes end to end.** `jupyter nbconvert --execute` completes with
exit 0. 66 stages, all with their outputs present.

**1,364 of 1,364 harness checks reproduce.** Table 1 in full, all 130 cells across ten
arms; Table 2's nine recovery counts; Table 5's Orai yield; Table 6's cost
figures; the cohort counts; the determinism evidence; and 37 of 37 shipped figure
assets byte-identical to the file the pipeline writes.

Establishing Table 1's gates was the substantive part. Four different gates are in
play and two of them are near-native:

| Gate | Definition |
| --- | --- |
| Validity | `pb_valid` |
| Near-native, Table 1 | `rmsd <= 2`, **not** conditioned on validity |
| Near-native, Table 6 | `pb_valid AND rmsd <= 2` |
| Form | `bestfit_rmsd <= 1 AND rmsd < 1000` |
| Triple | `pb_valid AND rmsd <= 2 AND bestfit_rmsd <= 1` |

The two near-native definitions are genuinely different and both are printed,
which is why AutoDock reads 217 complexes in Table 1 and 214 in Table 6. Both are
checked, so the difference cannot quietly collapse. The `rmsd < 1000` guard in the
form gate excludes exploded poses, whose best-fit RMSD can be small while the pose
is nowhere near the site.

**The refusal guards fire.** Forcing a `never` stage and a `verify` stage both
refuse with their reasons; a normal stage runs. Forcing everything at once is
rejected outright. This test caught the ordering bug described in section 3.2.

**No config was rewritten.** `git status Scripts/Docking/` after a full notebook
run shows the same five modified files it showed before, all last touched between
20 and 30 August, days before this work.

**The environment file is correct.** The regenerated `vina.yml` pins Python
3.12.12 and RDKit 2025.9.1.

## 7. Running it

```bash
conda activate vina
cd /home/manndo/master_dev
jupyter lab Thesis_Reproduction.ipynb     # or nbconvert --execute
```

Set `RUN_MODE` in the second cell:

| Mode | Effect |
| --- | --- |
| `verify` | Check outputs, execute nothing. The default. |
| `run-missing` | Also execute stages whose outputs are absent. |
| `force` | Also re-execute the stages named in `FORCE_STAGES`. |

`force` requires an explicit stage list. The `never` and `verify` classes refuse
under every mode.

Each run writes `posebusters_results/_reproduction/run_manifest.json`, recording
the environment, the determinism evidence, the canonical trees, every stage and
what happened to it. That is what tells drift from difference on a later run.
